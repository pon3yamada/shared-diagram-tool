# 図解ツール（diagram-tool）

わからない言葉やしくみを AI に伝えるだけで、初めて聞く人にもわかる図解ページを自動で作ってくれるツールです。

検索してもよくわからなかったことが「なるほど」に変わります。

- **前提知識がなくても読める** — 専門用語は出てきた場所で必ずわかりやすく解説されます
- **いきなり難しくならない** — まず全体像を見せてから、細かい話に入ります
- **文字の壁にならない** — カード・ステップ図・比較表など、目で見てわかる構成です
- **毎回きれいな図解ができる** — テンプレートと模範回答をもとに、安定した品質で生成されます
- **スマホでも見やすい** — 画面サイズに合わせてレイアウトが自動で調整されます

## 受け取り方（最初に 1 回）

この道具を、GitHub から自分のパソコンに写します（これを「clone」と言います）。いちばん簡単なのは、ふだん使っている AI のチャット欄に次の文を貼るやり方です。

```text
https://github.com/pon3yamada/shared-diagram-tool.git を ~/shared-diagram-tool に clone してください。
```

自分で打つときは、**ターミナル**（文字でパソコンに指示するアプリ。Mac は「ターミナル」、Windows は「PowerShell」）を開いて、次を打ちます。

```bash
git clone https://github.com/pon3yamada/shared-diagram-tool.git ~/shared-diagram-tool
```

- 「git が見つからない」と言われたら、Git（ファイルの変更を記録する道具）がまだ入っていません。AI に「Git を入れたい」と頼んでください
- 新しい版を取り込むとき: AI に「~/shared-diagram-tool を pull して」と頼むか、ターミナルで `git -C ~/shared-diagram-tool pull` と打ちます

## まず見てみる

`output/sample/` フォルダにお手本の図解が 3 つ入っています。
どれかひとつをブラウザ（Chrome、Safari など）にドラッグ＆ドロップして開いてください。

- **Gitの仕組み** — `output/sample/git.html`
- **LLMの仕組み** — `output/sample/llm.html`
- **Cursorの仕組み** — `output/sample/cursor.html`

## 使い方（3ステップ）

```
  ① このフォルダで AI を開く
              ↓
  ② チャットで「○○を図解して」と依頼
              ↓
  ③ output/ にできた HTML をブラウザで開く
```

### ステップ 1: このフォルダで AI を開く

clone した `~/shared-diagram-tool` のフォルダで、ふだん使っている AI（Claude Code・Cursor・Codex など）を開きます。

- Claude Code: ターミナルで `cd ~/shared-diagram-tool` してから `claude`。デスクトップアプリならこのフォルダを選ぶ
- Cursor: 「File → Open Folder」でこのフォルダを開き、Agent モードのチャットを使う
- Codex など: このフォルダで起動する

コードを書いたり、ファイルを編集したりする必要はありません。

### ステップ 2: チャット欄で図解を依頼する

AI のチャット欄に、知りたいことを書いて送信します。

```
APIについて図解して
```

### ステップ 3: 図解を確認する

AI が図解を作り、`output/` フォルダに保存します。
できた `.html` ファイルをブラウザにドラッグ＆ドロップして開いてください（手動で開きます）。

## 手元の資料を図解する

別のフォルダにある資料（議事メモ・手順書など）を見て図解することもできます。資料の場所をそのまま伝えてください。

例:

```
~/Documents/業務マニュアル/受注の流れ.md を見て、
受注から発送までの流れを図解して
```

資料を渡したときは、AI はウェブ検索よりその資料を優先します。

## 図解を共有するには

### PDF で共有する（おすすめ・準備不要）

図解ページの右上にある「PDF」ボタンを押すと、印刷画面が開きます。
保存先を「PDF」にすれば、そのままファイルとして保存できます。

### URL で共有する

図解を surge.sh というサービスに置いて、URL で見られるようにします。手元で見るだけなら、この準備は要りません。

**公開する前に、どうなるかを知っておいてください。** 公開した図解は**検索には出ませんが、URL を知っている人は誰でも見られます**。しくみは [docs/publishing.md](docs/publishing.md) にまとめています。公開する図に API キーやパスワードなどの「鍵」は絶対に書かないでください。

#### 最初の設定（1 回だけ）

1. Node.js を入れる（入っていなければ、チャット欄で「図解を公開したい」と伝えると AI が案内します）
2. surge のアカウントを作る。**自分のパソコンの「ターミナル」のアプリ**（Mac は「ターミナル」、Windows は「PowerShell」）を開いて、次を打ちます:

   ```bash
   npx surge login
   ```

   メールアドレスを打って Enter → パスワードを決めて打って Enter（打った文字は画面に出ませんが、正常です）。確認メールが届いたら、中のリンクを押します。

   **パスワードは AI のチャット欄に打たないでください。** チャット欄に打った文字は AI に送られ、会話の記録にも残ります。

#### 公開する

チャット欄で「この図解を公開して」と伝えます。初回だけ「URL に入れる名前（ローマ字）」を聞かれます。

公開 URL は次の形になります:

```text
https://diagram-git-taro-k3x9.surge.sh
        └ 図の題名 └ 名前 └ ランダムな 4 文字
```

ランダムな 4 文字が付くので、題名から URL を当てられにくく、同じ題名の図をほかの人が公開してもぶつかりません。同じ図を公開し直したときは、前と同じ URL のまま中身が新しくなります。

## 含まれるスキル

| スキル | 用途 | 呼び方の例 |
|---|---|---|
| `creating-visual-explainers` | 図解HTMLを作る | 「○○を図解して」 |
| `creating-skills` | スキル自体を作る・改善する（後から使う） | 「スキルを作って」 |

スキルは `.claude/skills/` にあります。どの AI から開いても、入口の `AGENTS.md` を読んでスキルの手順に従うようにしてあります。

## フォルダの中身

```text
shared-diagram-tool/
├── AGENTS.md            ← AI への入口（どの AI でも読む）
├── CLAUDE.md            ← Claude Code 用（AGENTS.md を読み込むだけ）
├── .claude/skills/
│   ├── creating-visual-explainers/
│   └── creating-skills/
├── docs/
│   ├── publishing.md    ← 公開のしくみ（答え合わせ用）
│   └── maintenance.md   ← 保守の手順（配布者向け）
├── output/
│   └── sample/          ← お手本
├── tools/
│   └── check.sh         ← 配布物の検査（配布者向け）
├── .gitignore
└── README.md
```

## 困ったとき

### 「base.html が見つかりません」と言われた

`~/shared-diagram-tool` のフォルダそのもので AI を開いているか確認してください（別のフォルダで開くと、図解の雛形が見つかりません）。

### 図解がうまく生成されない

チャット欄に「エラーが出ました」と伝えてください。

### その他

何が起きても、まずはチャット欄で AI に状況を伝えてください。
